## Correction — fixture serialization aligned with Jackson 3
The original handoff's response fixture was generated by hand-constructing a Jackson 2
`com.fasterxml.jackson.databind.ObjectMapper` with a manually registered `JavaTimeModule`,
described as "Spring Boot's default auto-configuration." That description was inaccurate and
unverified: GradeOps AI runs Spring Boot 4.1 / Jackson 3, whose auto-configured mapper is
`tools.jackson.databind.json.JsonMapper` (package `tools.jackson.*`), and Jackson 3's databind
module has built-in `java.time` support — `JavaTimeModule` is a Jackson 2 class that does not
exist in Jackson 3 and was never actually exercised by the running application. This section
records the fix; see "Response fixture" and "Tests" below for the corrected artifacts, and the
durable rule now recorded at
[`agents/docs/adr/2026-07-28-jackson-3-json-serialization.md`](../../adr/2026-07-28-jackson-3-json-serialization.md).

- **`tools.jackson.databind.json.JsonMapper` used**: yes, exclusively — obtained from the Spring
  `ApplicationContext` via `@Autowired` inside a `@JsonTest`-annotated test class (the lightest
  slice that auto-configures the real Jackson bean without a manually built mapper).
- **Auto-configured bean, not a hand-built one**: confirmed — no test in this module constructs
  an `ObjectMapper`/`JsonMapper` manually; `@JsonTest` triggers the same
  `JacksonAutoConfiguration` the running application uses.
- **Fixture location**: `agents/src/test/resources/fixtures/assessment-execution-response.json`
  (a physical, checked-in golden file — not only the copy embedded below in this handoff).
- **Contract test location**:
  `agents/src/test/java/cl/gradeops/ai/agents/assessment/infrastructure/adapter/in/web/response/AssessmentExecutionResponseContractTest.java`
  — asserts `provider`/`model` presence and value, asserts the real `Instant` string format
  Jackson 3 produces, and asserts the live-serialized DTO's `JsonNode` tree equals the fixture
  file's parsed tree (verified to fail when either side is changed without the other — see
  below).
- **Regression guard**:
  `agents/src/test/java/cl/gradeops/ai/agents/shared/architecture/JacksonUsageGuardTest.java` —
  scans `agents/`'s own `src/main`/`src/test` (never dependency jars) for the Jackson 2
  `ObjectMapper` FQN, `new ObjectMapper(...)`/`new JavaTimeModule(...)`, and the Jackson 2
  `JavaTimeModule` FQN; fails the build if any of these reappear.
- **Dependency inspection** (`./mvnw -Pdemo dependency:tree`, filtered to `jackson`):
  ```text
  org.springframework.boot:spring-boot-starter-jackson:4.1.0
    org.springframework.boot:spring-boot-jackson:4.1.0
      tools.jackson.core:jackson-databind:3.1.4        ← Jackson 3, backs our JsonMapper bean
  net.logstash.logback:logstash-logback-encoder:8.0
    com.fasterxml.jackson.core:jackson-databind:2.21.4  ← Jackson 2, Logstash's own log encoder
  org.springframework.ai:spring-ai-google-genai (Gemini adapter, -Pdemo)
    com.google.genai:google-genai:1.58.0
      com.fasterxml.jackson.datatype:jackson-datatype-jdk8:2.21.4   ← Jackson 2, internal to that SDK client
      com.fasterxml.jackson.datatype:jackson-datatype-jsr310:2.21.4 ← Jackson 2, internal to that SDK client
  org.springframework.ai:spring-ai-openai (Groq adapter, OpenAI-compatible client, -Pdemo)
    com.openai:openai-java-core:4.39.1
      com.fasterxml.jackson.module:jackson-module-kotlin:2.21.4 (runtime)
  ```
  Every Jackson 2 databind/datatype dependency present in the tree is transitively introduced by
  a third-party SDK client (Google GenAI client, OpenAI-compatible client, Logstash's log
  encoder) for that library's own internal HTTP/logging serialization — none of it is imported
  or constructed anywhere in `agents/`'s own `src/main`/`src/test` (confirmed by the grep in the
  correction request and by `JacksonUsageGuardTest`). No dependency was removed: each one was
  traced to its actual introducer first, per the instruction not to remove a transitive
  dependency without first confirming who introduces it and whether it participates in runtime
  — none of these do, for `agents/`'s own request/response serialization.
- **Confirmation**: `agents/`'s own maintained code (`src/main`, `src/test`) contains zero uses
  of Jackson 2 `com.fasterxml.jackson.databind.ObjectMapper` or a manually registered
  `JavaTimeModule` — enforced going forward by `JacksonUsageGuardTest`.

## Response schema
Full field list of `AgentExecutionLogPayload` after this change, in declared order:

```java
public record AgentExecutionLogPayload(
        UUID agentExecutionId,
        String agentName,
        String provider,          // NEW — resolved provider name, e.g. "gemini" / "groq"
        String model,
        String promptVersion,
        String inputHash,
        String outputHash,
        Integer estimatedInputTokens,
        Integer estimatedOutputTokens,
        Double costEstimate,
        String status,
        String errorCode,
        Instant startedAt,
        Instant finishedAt) {
}
```

`provider` is populated from `AssessmentGenerationPortSelector.SelectedProvider.name()` at every
point `model` is already populated in `AssessmentAgentOrchestrator`:
- Successful generation: `selected.name()` (non-null).
- `MALFORMED_OUTPUT` failure (output validation failed, or the port call itself threw after
  provider resolution already succeeded): the already-resolved `provider` parameter (non-null —
  resolution happened before this failure).
- `INVALID_COMMAND` failure (validation rejects the command before `selector.resolve(...)` is
  ever called): left unset — `null`, same as `model` already behaves in this path, since
  resolution never happened.
