# Principios y gobierno UI/UX

## Principios

- Priorizar la tarea docente sobre la estética.
- Reducir carga cognitiva, pasos y decisiones innecesarias.
- Diseñar primero el flujo; luego la interfaz.
- Mantener consistencia mediante tokens y componentes reutilizables.
- Considerar desde el inicio estados de carga, vacío, error, éxito y permisos.
- Cumplir WCAG 2.2 nivel AA como base.
- Tratar la IA como asistencia explicable y reversible, no como autoridad.
- Validar decisiones con evidencia observable.

## Responsabilidades

| Rol | Responsabilidad |
|---|---|
| Product Owner | Alcance, prioridad y resultado de negocio |
| UX | Investigación, arquitectura, flujos y validación |
| UI | Lenguaje visual, componentes y prototipos |
| Frontend | Implementación, accesibilidad y rendimiento |
| QA | Cobertura funcional, visual y de accesibilidad |
| Docente validador | Evidencia de utilidad, comprensión y eficiencia |

## Registro de decisiones

Cada decisión relevante debe registrar:

- problema;
- opciones consideradas;
- evidencia utilizada;
- decisión;
- consecuencias;
- responsable;
- fecha;
- condición de revisión.

## Fuentes de verdad

| Elemento | Fuente |
|---|---|
| Necesidades y tareas | Repositorio de investigación UX |
| Flujos aprobados | Figma |
| Tokens y componentes | Design system versionado |
| Comportamiento funcional | Historias y criterios de aceptación |
| Implementación | Repositorio de código |

## Política de IA generativa

Los resultados de Stitch, Figma Make y v0 son propuestas. No se aceptan sin revisión de consistencia, accesibilidad, adecuación al dominio y compatibilidad con el sistema de diseño.
