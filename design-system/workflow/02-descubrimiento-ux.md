# Descubrimiento UX

## Objetivo

Comprender el trabajo real del docente antes de definir pantallas o componentes.

## Entradas

- visión y alcance del producto;
- historias de usuario;
- procesos docentes actuales;
- restricciones técnicas y regulatorias;
- métricas disponibles;
- feedback previo.

## Actividades

1. Identificar segmentos y contextos de uso.
2. Definir trabajos principales y resultados esperados.
3. Mapear proceso actual, fricciones, riesgos y soluciones informales.
4. Priorizar tareas por frecuencia, impacto y criticidad.
5. Formular hipótesis verificables.
6. Definir métricas UX.

## Artefactos mínimos

- perfiles conductuales, no demográficos;
- mapa de tareas;
- journey actual;
- inventario de problemas;
- hipótesis priorizadas;
- requisitos UX;
- restricciones y supuestos.

## Plantilla de requisito UX

```text
Cuando [contexto], el usuario necesita [tarea],
para obtener [resultado].
La solución será aceptable si [métrica o evidencia].
```

## Métricas recomendadas

- tasa de finalización;
- tiempo por tarea;
- errores y recuperaciones;
- pasos y cambios de contexto;
- solicitudes de ayuda;
- confianza percibida;
- aceptación, edición o rechazo de resultados generados por IA.

## Criterio de salida

Existe una definición priorizada de usuarios, tareas, problemas, riesgos y métricas. No se avanza con necesidades formuladas únicamente como listas de funcionalidades.
