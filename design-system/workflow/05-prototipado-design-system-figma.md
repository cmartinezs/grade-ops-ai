# Prototipado y design system en Figma

## Objetivo

Transformar la dirección seleccionada en una especificación interactiva, consistente y preparada para implementación.

## Proceso

1. Importar o reconstruir la dirección visual.
2. Definir variables y tokens.
3. Crear componentes base.
4. Componer patrones y pantallas.
5. Incorporar variantes y estados.
6. Construir prototipo navegable.
7. Documentar comportamiento y contenido.

## Tokens mínimos

- color semántico;
- tipografía;
- espaciado;
- tamaño;
- borde y radio;
- elevación;
- movimiento;
- breakpoints;
- foco y estados interactivos.

## Componentes mínimos

- botones y enlaces;
- campos y validación;
- selección y búsqueda;
- tablas y listas;
- navegación;
- tarjetas;
- modales y paneles;
- alertas y notificaciones;
- progreso;
- estados vacíos;
- componentes de revisión de IA.

## Reglas

- Usar propiedades y variantes; evitar duplicación.
- Nombrar por función, no por apariencia.
- Separar tokens primitivos y semánticos.
- Documentar contenido, interacción y accesibilidad.
- Usar datos representativos, no `Lorem ipsum`.
- Diseñar desktop y móvil según contexto real, no por reducción mecánica.

## Handoff

Cada pantalla debe indicar:

- componentes utilizados;
- reglas responsive;
- estados;
- navegación;
- validaciones;
- permisos;
- contenido;
- eventos analíticos;
- criterios de aceptación relacionados.

## Criterio de salida

El prototipo cubre flujos críticos, componentes, estados y comportamiento responsive sin decisiones esenciales pendientes para desarrollo.
